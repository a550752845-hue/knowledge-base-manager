# 完整逐字稿：先校准再加速

讲者：很多团队说自己缺的是整理速度，但我看到的真实问题不是慢，而是返工。大家拿到逐字稿，先挑最响亮的句子做卡片，三天后才发现开头的问题、结尾的限制和中间的反例根本没有被放在一起。

今天讨论的对象是需要把访谈、课程和会议记录变成长期知识资产的内容团队。前提是原始材料仍然可读，而且我们的目标不是当天发一条内容，而是让半年后的同事还能正确调用。

## [01:05-02:25] 核心主张与隐含前提

讲者：我的主张是，先完成整源逻辑图，再决定是否拆资产。隐含前提有两个：第一，来源本身可能前后修正；第二，一句好听的话不一定有独立检索价值。

“先把路画完整，再决定在哪里开门。”这句话适合提醒团队，但它本身不是方法。方法必须说明问题、前提、推理、反例、结论和适用边界。

## [02:25-04:20] 推理链与未经核验的例子

讲者：为什么顺序重要？如果先摘句子，卡片会继承局部语境；局部语境进入索引后，又会被当成完整结论；未来生成时，模型只看到卡片，不会自动知道缺失了什么。反过来，整源图先记录主张之间的关系，后续每个资产都能回到来源位置。

## [04:20-06:05] 反例与条件

讲者：并不是每份材料都值得深做。比如只有两句状态通知、没有论证结构的记录，注册来源和短处置就够了。另一个反例是已有可靠结构化索引的法规文本；这时应保留原生条款层级，而不是强行套用口语逐字稿模板。

所以“整源理解”不等于无限加工。它的强度取决于来源等级、未来用途、时效和风险。

## [06:05-07:35] 异议、转折与限定结论

讲者：有人会问，先做完整图是不是更慢？短期看会多一次合并，但真正要比较的是从首次阅读到后续复用的总成本。如果来源低价值，应该降低处理深度；如果来源是核心框架，省掉整源图只是把成本推给未来调用者。

因此，我把结论限定为：对 S 级和 A 级逐字稿，先重建完整逻辑，再提取少量有明确检索用途的资产；对 B 级和 C 级来源，不要假装做了同样深度。
