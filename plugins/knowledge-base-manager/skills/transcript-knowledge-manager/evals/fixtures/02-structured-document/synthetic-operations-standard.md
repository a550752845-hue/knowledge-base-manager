# 合成灯塔台交接操作规范

## 1. 目的、受众与范围

本规范供虚构的灯塔台值守演练使用，目标是在不丢失告警上下文的情况下完成班次交接。它不适用于真实航运、应急或人身安全决策。

## 2. 术语与定义

| 术语 | 定义 | 锚点 |
| --- | --- | --- |
| 活跃告警 | 在交接时尚未关闭且有下一动作的合成事件 | 表 2-1 行 1 |
| 所有者 | 对下一动作负责的角色，不是个人姓名 | 表 2-1 行 2 |
| 冻结窗口 | 交接前停止非必要配置变更的 15 分钟窗口 | 表 2-1 行 3 |

## 3. 容量规则

每班可安全接收的合成告警容量按下式估算：

```text
capacity = floor(available_minutes / 6) - unresolved_high_risk
```

其中 `available_minutes` 只计交接专用时间。该公式是本来源提出的操作规则，不代表独立核验事实。

| 风险级别 | 最大并行数 | 必要证据 |
| --- | ---: | --- |
| 低 | 5 | 状态与下一动作 |
| 中 | 3 | 状态、下一动作、回退点 |
| 高 | 1 | 完整时间线、审批状态、回退点 |

## 4. 标准程序

### 4.1 前置条件

1. 当前班次已停止非必要配置变更。
2. 告警清单有稳定事件 ID。
3. 接班角色可以读取演练环境，但不自动获得受限附件权限。

### 4.2 有序步骤

1. 按事件 ID 核对活跃告警数量。
2. 为每个告警记录当前状态、最后证据、下一动作和角色所有者。
3. 计算第 3 节容量。
4. 若活跃告警数小于或等于容量，进入步骤 5；否则进入 4.3 的超载分支。
5. 接班角色复述最高风险告警和首个动作。
6. 交班角色确认复述结果，写入交接完成时间。

### 4.3 超载分支

当活跃告警数超过容量时：

1. 冻结新的低风险演练任务。
2. 将无下一动作的告警标为待澄清，不得伪造动作。
3. 只移交容量以内的最高风险告警。
4. 把剩余告警写入下一轮队列并记录原因。

### 4.4 输出

输出必须包含事件 ID、风险、当前状态、证据锚点、下一动作、角色所有者和交接时间。

## 5. 失败与恢复

如果接班角色无法复述最高风险告警，交接失败。恢复方式是返回 4.2 步骤 2，补齐证据与下一动作；不得仅重复结论。若事件 ID 重复，停止写入并进入数据质量队列。

## 6. 例外与边界

- 受限附件不可因为交接而降级为 internal。
- 公式只用于本合成演练，不用于真实人员排班。
- 缺少证据的告警可以登记为来源主张，但不能标为已核事实。
- 紧急口头信息必须在交接完成前补写锚点。
